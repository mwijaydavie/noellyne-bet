# Noellyne Bet

Live football streaming + AI daily picks. Flutter viewer and admin apps, Supabase backend, Cloudflare/Vercel delivery.

Built on the MIT-licensed [NCA football-stream-app](https://github.com/nyeinchanaung75299-eng/football-stream-app) engine, re-skinned and extended.

## Design

Warm editorial glassmorphism — alabaster canvas, terracotta ambient glow, frosted glass cards, matte obsidian actions. Full spec: [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md).

- Live interactive preview: `node preview/server.mjs` → open the printed URL (Lobby · Daily Picks · Match Theatre, light + dark).
- Flutter tokens: `user_app/lib/app_theme.dart`
- Shared UI kit: `user_app/lib/design/noellyne_ui.dart`
- Font: Plus Jakarta Sans (bundled, OFL)

## Apps

| Path | What it is |
|---|---|
| `user_app/` | Viewer app (`football_viewer` 10.0.0) — Live, Daily Picks, Channels, Match Theatre |
| `admin_app/` | Admin dashboard (`football_admin` 3.0.0) — matches, streams, fixtures, channels, health |
| `supabase/` | Schema, migrations, Edge Functions |
| `cloudflare/`, `vercel/` | Protected gateway + network fallbacks |
| `preview/` | Static design preview (no Flutter SDK needed) |
| `docs/` | Integration docs — start with [`docs/N8N_DAILY_PICKS.md`](docs/N8N_DAILY_PICKS.md) |

## Team badges

`TeamCrest` guarantees a badge for **every** fixture: the feed's crest when it
has one, otherwise a curated club-colour crest (90+ clubs, including NBC Premier
League sides), otherwise a deterministic hue + initials. Nobody ever sees a
grey shield.

## Daily Picks (n8n)

The Daily Bets feed renders structured JSON from the n8n pipeline as filterable cards with odds, confidence, AI reasoning and a one-tap deep-link into the live player. Contract and wiring: [`docs/N8N_DAILY_PICKS.md`](docs/N8N_DAILY_PICKS.md).

## Run

```bash
cd user_app && flutter pub get && flutter run          # viewer
cd admin_app && flutter pub get && flutter run         # admin
node preview/server.mjs                                # design preview
```

## Configuration (dart-define)

| Define | Default | Purpose |
|---|---|---|
| `SUPABASE_URL` | upstream project (on) | Realtime match updates, DB fallback source, channel ordering, cloud Daily Picks |
| `SUPABASE_ANON_KEY` | publishable key | Supabase client (RLS-protected, safe to ship) |
| `PUBLIC_API_BASE` | Cloudflare feed | Match list |
| `UPDATE_MANIFEST_URL` | our `viewer-latest/latest.json` | In-app updater |

Supabase is **on by default** and every call is guarded, so an unreachable
project degrades to the public feed + 60s polling instead of breaking the app.

In-app updates are served from **this repo's** `viewer-latest` release; the CI
job rewrites `latest.json` (version, build, sha256, size) on every APK build.

## Get the APK

Every push that touches `user_app/` builds an installable APK on GitHub Actions
(workflow **Build Noellyne Bet APK**):

1. Open the repo's **Releases** page — each build publishes a release tagged
   `apk-<run number>` with a direct APK download.
2. Or open **Actions → Build Noellyne Bet APK → latest run → Artifacts**.

APK is debug-key signed for testing (not an updater release). Android platform
files, permissions, Media3 player deps and the launcher icon are generated by
the workflow, so nothing platform-specific is committed.
